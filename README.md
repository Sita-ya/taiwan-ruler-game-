# 世界的尺：背包客生存挑戰 — 架設與使用說明

這是純網頁（HTML + CSS + JavaScript）遊戲，不需要安裝或編譯。老師用 `teacher.html`，學生平板用 `student.html`。

## 資料夾內容

| 檔案 | 用途 |
|---|---|
| `teacher.html` / `teacher.js` | 教師控制台＋投影模式（單一螢幕用） |
| `projector.html` / `projector.js` | 獨立投影視窗（延伸螢幕用，只顯示、不控制） |
| `projection.js` | 投影畫面內容（投影模式、控制台預覽、投影視窗共用同一份） |
| `manifest.json`、`icon.png` | 讓 iPad「加入主畫面」後像 App 一樣全螢幕開啟 |
| `index.html` | 首頁（選學生／老師） |
| `student.html` / `student.js` | 學生端 |
| `config.js` | **所有國家資料、價格、教師口白、Firebase 設定** |
| `app.js`、`db.js`、`style.css` | 共用程式與樣式 |
| `database.rules.json` | Firebase 安全規則（要貼到 Firebase） |
| `assets/` | 插圖（`backpackers.jpg`、`postcard_*.jpg`）與 `assets/flags/`（國旗 SVG，flag-icons，MIT 授權） |
| `lib/` | Firebase、PDF、QR code 函式庫（已下載到專案內，不靠 CDN） |

上線時要上傳：`index.html`、`teacher.html`、`student.html`、`projector.html`、`teacher.js`、`student.js`、`projector.js`、`projection.js`、`app.js`、`db.js`、`config.js`、`style.css`、`manifest.json`、`icon.png`、`assets/`、`lib/`。**這個專案的 .js 檔都放在最外層（沒有 `js/` 資料夾）**，和 html 檔放同一層即可。`生成圖檔/`、`.md` 檔不用上傳。

## 零、先在自己電腦試玩（不用任何設定）

`config.js` 裡 Firebase 還是空的時候，遊戲會進入「**本機示範模式**」：資料只存在這台電腦的瀏覽器，**同一台電腦的不同分頁**就能當成老師和不同組的平板互相連動。適合先熟悉流程。

1. 把整個資料夾放在一個網站伺服器下開啟（直接雙擊 html 檔，部分瀏覽器會擋住功能）。最簡單的方式：先完成下面的 GitHub Pages 上線，再用網址試玩。
2. 開一個分頁進 `teacher.html`，另開幾個分頁進 `student.html`（每個分頁當作一台平板）。

---

## 一、設定 Firebase（約 10 分鐘，免費方案就夠）

1. 到 <https://console.firebase.google.com> 用 Google 帳號登入 →「**新增專案**」，名稱隨意（例如 `world-ruler`），Google Analytics 可以關閉。
2. 左側選單 **建構 → Realtime Database →「建立資料庫」**。位置選 `asia-southeast1（新加坡）`，模式選「**以鎖定模式啟動**」。
3. 左側選單 **建構 → Authentication →「開始使用」→ 登入方式 → 匿名 → 啟用 → 儲存**。（學生不用登入，系統會自動給每台平板一個匿名身分，用來判斷「這一組是哪台平板」。）
4. 回到 Realtime Database →「**規則**」分頁，把 `database.rules.json` 的全部內容貼上，按「發布」。
   - 規則的意思：任何人只能讀房間；只有「開房間的那台電腦」能改步驟與設定；學生平板只能寫入自己佔用的那一組。
5. 左上角齒輪 →「專案設定」→「一般」→ 最下方「您的應用程式」→ 按 `</>`（網頁）→ 取個名字 → 註冊。畫面會出現一段 `firebaseConfig`，把裡面的值貼到 `config.js` 最上面的 `FIREBASE_CONFIG`：
   ```js
   window.FIREBASE_CONFIG = {
     apiKey: "…", authDomain: "…", databaseURL: "https://xxxx-default-rtdb.asia-southeast1.firebasedatabase.app",
     projectId: "…", appId: "…"
   };
   ```
   `databaseURL` 如果沒顯示，到 Realtime Database 頁面最上面可以複製。
6. **Authentication → 設定 → 授權網域** 按「新增網域」，加入你的網站網域（例如 `你的帳號.github.io` 或 `xxx.netlify.app`）。沒加的話匿名登入會失敗。

> Firebase 的 `apiKey` 放在網頁裡是正常的（不是密碼），真正的保護來自上面的安全規則。

## 二、上線（二選一）

**GitHub Pages**：建一個 GitHub 儲存庫 → 把上面列的檔案上傳 → Settings → Pages → Branch 選 `main` / root → 儲存。幾分鐘後得到 `https://帳號.github.io/儲存庫名/`。

**Netlify（最簡單）**：到 <https://app.netlify.com/drop>，把整個資料夾拖進去，馬上得到網址。

網址：老師 `…/teacher.html`、學生 `…/student.html`。

## 三、上課當天流程

**課前**：用老師電腦打開 `teacher.html` → 第一次使用先設定教師密碼（只存在這台電腦）→ 選本局組數（4／5／6）與國家 →「開始新的一局」。投影到電子白板，按「📽 投影模式」。

> ⚠ **要用同一台電腦、同一個瀏覽器來控場。** 房間的控制權綁定在建立它的瀏覽器，換電腦／清除瀏覽資料後只能「檢視」與匯出海報，不能再控制。

| 步驟 | 老師做什麼 |
|---|---|
| 0 大廳 | 投影幕有房間代碼與 QR code。學生輸入代碼、選組別。控制台顯示各組是否加入。 |
| 1 開箱 | 按「🎲 抽籤」（或用下拉選單手動指定）→「下一步」。 |
| 2 搜尋 | 學生查資料卡、填答案。控制台看各組進度，**全部完成時「下一步」會閃動**。 |
| 3 第一回合 / 4 商店 / 5 第二回合 | 同上，等各組完成再按下一步。 |
| 6 數字排排站 | 投影模式，每按一次（→ 或空白鍵）出現一個國家，最後出現世界銀行線、提問、各組剩下的錢。 |
| 7 海報 | 學生可自行下載 PDF；老師到「海報總覽」可全部匯出。 |

**投影模式快捷鍵**：→ 或空白鍵＝下一步、← ＝上一步、P＝全班暫停、Esc＝離開投影模式。
**全班暫停**：控制台最上方紅色按鈕，學生平板立刻蓋上「👀 眼睛看老師」。

**投影預覽**：控制台右側（螢幕較窄時在上方）會即時顯示「投影幕目前的畫面」，點一下就進入投影模式。

### 控制台和投影畫面分開（電腦接電子白板、設定成「延伸」時）

1. 電腦接上電子白板後，按鍵盤 `Windows 鍵 + P` → 選「**延伸**」（選「複製」的話兩邊會一模一樣）。
2. 控制台按「🖥 開啟投影視窗」；若沒跳出來，網址列右邊點「已封鎖彈出式視窗」→「一律允許」→ 再按一次。
3. 用滑鼠按住新視窗的標題列，拖到白板那一邊。
4. 在白板上點「⛶ 全螢幕」（或按 `F`、或連點兩下畫面）。
5. 之後在筆電上看控制台操作，白板自動跟著換頁；要離開全螢幕按 `Esc`。

- 投影視窗**只顯示、不控制**：沒有任何換頁按鈕，也沒有換頁快捷鍵，學生在白板上亂點也改不到步驟。
- 重複按「🖥 開啟投影視窗」只會叫回同一個視窗，不會開一堆。
- 只有一個螢幕（「複製」）時，照舊用「📽 投影模式」。
- 練習模式（`?demo=1`）下也能用投影視窗，同一台電腦的視窗會即時同步。

### 讓學生平板全螢幕（隱藏網址列）

1. 學生都加入後，按控制台上方「📱 平板全螢幕」（按鈕變綠、出現 ✓）。
2. 每台平板出現黃色大按鈕，請學生點一下，網址列就消失。不小心退出的話大按鈕會再出現。控制台各組卡片會顯示「⛶ 全螢幕」或「⚠ 未全螢幕」。
3. 不需要時再按一次「📱 平板全螢幕」關閉，平板會自動離開全螢幕。
4. iPad 若出現「加入主畫面」說明，代表那台不支援網頁全螢幕，請課前用 Safari 打開學生網址 → 分享 → 加入主畫面，上課從主畫面「世界的尺」圖示打開。
5. 若學校 iPad 由資訊組統一管理（MDM，例如 Jamf），可請資訊組用「Web Clip（網頁剪輯）」把學生網址一次推送到所有 iPad 主畫面並勾選「全螢幕」。
6. Chromebook、Android 平板用黃色大按鈕即可。

為什麼不能由老師直接切換：瀏覽器規定「進入全螢幕」一定要使用者在那台裝置上親手點一下。iPad 上改用 Chrome 也沒用（Apple 規定 iPad 所有瀏覽器都用和 Safari 一樣的核心）。

> ⚠ **主畫面圖示和 Safari 的資料是分開的**：從主畫面圖示打開時，學生要**手動輸入一次房間代碼**、選回同一組（進度在雲端，選回同組就會接續）。掃 QR code 一定是開到 Safari，不會開到主畫面圖示。

**練習模式**：網址後面加上 `?demo=1`（例如 `teacher.html?demo=1`、`student.html?demo=1`），會改用本機示範模式，不會寫進 Firebase，適合自己在同一台電腦開多個分頁練習。

**各組卡片上的按鈕**
- **踢出**：讓這組換另一台平板用同一組別重新加入，進度與購物車會接續。
- **鎖定／解鎖**：暫時凍結某組平板。
- **重做第 1／2 回合**：清除該回合採買紀錄，讓該組重買（預設學生結帳後不能自己改）。
- 最下方「重新開始」會清空全部組別的作答。

## 四、匯出海報

- 控制台「**海報總覽**」分頁 →「全部匯出」得到一個多頁 PDF（每組一頁 A3）；按單張縮圖只匯出該組。
- 學生平板在步驟 7 也可按「下載 PDF」下載自己那一組。
- 列印請選 A3、「實際大小」（不要縮放）。
- 平板若是 iPad，下載的 PDF 會在「檔案」App；若匯出失敗請改用老師電腦匯出。

## 五、歷史紀錄與重新匯出

回到控制台首頁（「← 回首頁」），「歷史紀錄」列出本電腦開過的房間（保留 30 天，超過會自動清掉）。按「打開」即可重新匯出海報。也可以直接輸入 4 位數房間代碼打開。
資料保存在 Firebase，下課後或隔天都能匯出；若用另一台電腦打開，只能檢視與匯出。

## 六、修改資料（`config.js`）

- **國家資料卡**：`CONFIG.countries`（原始金額、換算算式、一天台幣、資料來源）。
- **價格**：`CONFIG.needs`（必需品）與 `CONFIG.store`（商店）。每個品項的 `p` 陣列順序是 **肯亞、印度、巴西、日本、美國、台灣**。
- **3 美元的台幣數字**：`wbLineTWD`（目前 98）。
- **教師口白**：`CONFIG.steps[].tip`。
- 修改後重新上傳 `config.js` 即可。

## 七、已完成的自我測試

在本機示範模式（瀏覽器多分頁）驗證過：

- 學生端依老師的步驟切換；全班暫停的遮罩立即出現與解除。
- 步驟 2：答案誤差 ≤ 2 元才算對，答錯顯示提示。
- 步驟 3～5：錢不夠的選項變灰、可取消、每欄必須決定才出現結帳、結帳與商店完成都有確認視窗。
- 重新整理學生頁後自動回到原本步驟與購物車；踢出後該組可重新加入並保留進度。
- 價格計算（直接用 `config.js` 的數字算）：
  - 各國「早餐＋兩餐自己煮＋合租」最低花費：肯亞 127、印度 78、巴西 180、日本 367、美國 739、台灣 288。
  - 第二回合 98 元：印度買齊必需品（含手機）剩 16 元；日本早餐＋一餐自己煮剩 1 元。
  - 肯亞第一回合（67 元）會有買不起的類別（住），並顯示提醒卡。
- 數字排排站：對數刻度，22／43／67／98 分得開，標籤為實際金額，依序出現。
- 海報：6 組輸出皆為 A3 比例（2807×3967 像素）、中文字正常、明細表不超出頁面（含最多額外商品的情況）。

**投影視窗與平板全螢幕（本機示範模式驗證）**：投影視窗開啟後顯示大廳（代碼＋QR code）、老師按下一步會同步換頁、視窗內只有「⛶ 全螢幕」一個按鈕且方向鍵／空白鍵／P 都不會改步驟；數字排排站只有「剛出現的國家」播動畫，資料小更新或重新整理不重播；1366×768、1440×900 下工具列都是一行；平板 1024×768 的黃色大按鈕置中、46px 字；全班暫停蓋板在全螢幕按鈕之上；模擬「不支援全螢幕的 iPad」會出現加入主畫面教學卡，按「知道了」後不再出現。

**還沒驗證**：真正連到 Firebase 的行為（匿名登入、安全規則、多台實體平板同時連線、學生寫入 `state/fs` 會被拒絕）、實體 iPad 的全螢幕／加入主畫面、雙螢幕「延伸」與把視窗拖到白板。我無法替你的 Firebase 帳號操作，請在正式上課前用 2～3 台裝置完整走一遍。

## 八、常見問題

- **學生輸入代碼後找不到房間**：確認 `config.js` 的 Firebase 設定已填、授權網域已加、規則已發布。
- **畫面顯示「連線失敗」**：多半是匿名登入沒啟用或網域沒授權。
- **學生端右下角的小圓點**：綠色＝已連線；紅色＝斷線（重新連線後會自動同步，已做的選擇不會遺失）。
- **某組平板壞了**：控制台按該組「踢出」，換平板用同一組別加入。
- **教師密碼忘了**：控制台登入頁清除瀏覽器網站資料即可重設（歷史紀錄清單也會清掉，但雲端房間仍可用代碼打開）。
- 本遊戲**不蒐集學生姓名**，學生只選組別。
